# Agent Spec: Google Cloud Support Case Management Agent

## Overview
An enterprise-grade AI Agent built on Google ADK (`google-adk`) and FastAPI that helps Google Cloud customers and partners submit, query, comment on, upload attachments to, escalate, and close Google Cloud Support Cases via the Google Cloud Support API v2 (`cloudsupport.googleapis.com`).
Supports dual-mode execution:
- **MOCK mode (default for local dev/demo)**: Full stateful SQLite simulation of Google Cloud Support API v2 cases, classifications, comments, attachments, and escalations without requiring a paid Support subscription.
- **LIVE mode**: Calls the real `google-cloud-support` v2 API via backend Service Account / ADC, enforcing `test_case=True` by default for safety and verifying `project_id` against an application-level allowlist.

## Example Use Cases
1. **Guided Case Creation with HITL Confirmation**:
   - User: "帮我在项目 gcp-prod-app-01 提一个工单，我们的 Cloud SQL 实例连不上了，报错 connection timeout"
   - Agent searches `search_case_classifications(query="Cloud SQL")`, checks required fields (severity, project_id, display_name, description), and calls `prepare_case_draft(...)` to render a structured Confirmation Card in the Web UI before any case is actually created.
   - Once the user clicks "确认提交" (or confirms the draft ID), `confirm_and_create_case(draft_id=..., confirmed=True)` creates the case.
2. **Full Case Lifecycle Management**:
   - Query open/closed cases for a project (`list_support_cases`) and inspect details, comments, and attachments (`get_support_case_details`).
   - Add diagnostic logs or replies (`add_case_comment`).
   - Request escalation with mandatory HITL preview (`prepare_escalation_draft` -> `confirm_and_escalate_case`).
   - Close resolved cases (`close_support_case`).

## Tools Required
- `search_case_classifications(query: str)`: Searches valid Google Cloud Support case classifications.
- `prepare_case_draft(project_id: str, display_name: str, description: str, severity: str, classification_id: str, classification_display_name: str, subscriber_emails: str, time_zone: str)`: Creates a pending case draft for HITL user confirmation.
- `confirm_and_create_case(draft_id: str, confirmed: bool)`: Executes `cases.create` only after explicit user confirmation of the draft.
- `list_support_cases(project_id: str, state_filter: str)`: Lists support cases under an authorized GCP project.
- `get_support_case_details(case_name: str)`: Fetches full case details, comments history, and attachment metadata.
- `add_case_comment(case_name: str, body: str)`: Posts a comment to an existing support case (`comments.create`).
- `prepare_escalation_draft(case_name: str, reason: str, justification: str)`: Creates a pending escalation draft for HITL user confirmation.
- `confirm_and_escalate_case(draft_id: str, confirmed: bool)`: Executes `cases.escalate` only after explicit user confirmation.
- `close_support_case(case_name: str)`: Closes an existing support case (`cases.close`).

## Constraints & Safety Rules
- **HITL Confirmation Gate**: Never create or escalate a support case without first creating a draft (`prepare_case_draft` / `prepare_escalation_draft`) and receiving explicit confirmation (`confirmed=True`). Enforced both in tool logic and `before_tool_callback`.
- **Project Authorization Allowlist**: Every tool and API endpoint validates that the target `project_id` is in the authorized project allowlist.
- **Test Case Safety**: In LIVE mode, `test_case=True` is enforced by default unless explicitly overridden by administrator configuration.
- **Web Security**: Strict CSP headers, HttpOnly/SameSite session cookies, Double-Submit CSRF protection on state-changing POST endpoints, magic-byte validated attachment uploads outside web root, parameterized SQLite queries, and zero `innerHTML` usage on the frontend.

## Success Criteria
- Agent accurately guides users to provide missing required fields before drafting a case.
- Agent matches valid Google Cloud Support classifications prior to drafting.
- Agent never bypasses the draft confirmation gate for `confirm_and_create_case` or `confirm_and_escalate_case`.
- All unit tests, API integration tests, and Web UI workflows pass on `127.0.0.1`.
