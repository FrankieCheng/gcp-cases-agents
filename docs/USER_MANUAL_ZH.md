# Google Cloud Support 智能工单系统 — 用户与云运维操作手册

本手册面向日常使用本系统的**研发工程师、云平台运维（Cloud SRE / Ops）、值班经理（Incident Commander）与客户技术支持团队**，介绍如何通过飞书机器人（及 Web 控制台）高效、安全地完成 Google Cloud 技术支持工单的全生命周期管理。

---

## 1. 核心设计理念与安全护栏（HITL）

本系统基于 **Google ADK (`gemini-4-hydrogen`) + Google Cloud Support API v2** 构建，采用严格的 **Human-in-the-Loop（人工确认护栏）** 架构：

| 操作类别 | 包含动作 | 执行机制 |
|---|---|---|
| **AI 自动执行类**（低风险/高频协作） | 查询工单列表与详情、跨项目搜索、多模态识图提取报错、匹配官方问题分类、起草/在线修改草稿、追加回复评论、上传/读取诊断附件、调整在途工单严重级别与抄送邮箱、生成交接班巡检简报 | 对话下达指令后，Agent 校验项目白名单（RBAC）与敏感信息脱敏后**立即完成**。 |
| **人工卡片确认类**（高影响/不可逆状态变更） | **正式创建工单 (`cases.create`)**、**正式申请升级 (`cases.escalate`)**、**正式关闭工单 (`cases.close`)** | Agent **绝不会直接执行**（即便在文字里说“帮我直接确认”也不会绕过），只会向会话发送一张**橙色交互式确认卡片**；必须由**发起人、被授权接班同事或值班负责人**亲自点击卡片上的 **「确认提交」** 按钮才会调用 Google API。 |

## 2. 飞书机器人全场景使用指南

### 2.1 唤醒与群聊智能对话规则
- **私聊（单聊机器人）**：直接发送文字、截图或诊断文件即可，无需 `@`。
- **群聊（SRE War Room / 运维群）**：
  1. **首次发起**：通过 `@机器人` 唤醒（例如：`@CaseAgent 帮我提一个工单`）。
  2. **免 `@` 连续跟进**：唤醒后的 **10 分钟内**，您在同一群里继续回答机器人的追问、补充报错截图或修改草稿**无需每次都 `@`**；群里其他同事若针对当前工单补充提问（如“这个单子现在什么级别？”），机器人也会结合上下文自动识别并回复；同事间无关闲聊（如“中午吃什么”）机器人会自动保持静默。
  3. **引用卡片直接触发**：在群内直接「引用回复」机器人发出的任何工单确认卡片或通知卡片，无需 `@` 也无需输入工单号。

---

### 2.2 提报新工单（含防重检测、排障体检与 S1 全球接力提醒）

提报新工单只需包含三要素：**目标项目（未提则用默认项目）+ 故障现象/报错详情 + 严重级别（S1–S4，未提默认 S3）**。

#### 示例 1：一句话快速提单
> **您**：`@机器人 在 demo-core-prod 提个 S2 工单：生产 Cloud SQL 实例 prod-pg-01 从今天 14:20 UTC 起在 asia-east1 出现约 10% 连接超时，已排除防火墙问题，抄送 sre-oncall@example.com`

机器人会自动完成以下动作并弹出**待确认草稿卡片**：
1. **自动匹配官方产品分类**（如 `Cloud SQL > PostgreSQL > Connectivity`）；
2. **相似未关闭工单防重检测**：若同项目下已有症状相似的活跃工单，会在卡片与回复中醒目列出单号，防止多人重复报障；
3. **产品级黄金排障要素体检（非阻塞提示）**：自动检查是否遗漏了首轮排障关键信息（例如 BigQuery 缺 `Job ID`、GKE 缺集群/节点池名、Cloud Run 缺 `X-Cloud-Trace-Context`、通用缺时间窗或 Region），在卡片底部给出 `💡` 补充建议，避免提交后被工程师第一轮打回 `ACTION_REQUIRED`；
4. **S1 (P1) 紧急工单专项守护**：当提报 `S1` 工单时，若未填 7×24 值班订阅邮箱或描述为纯中文，系统会自动提醒补充值班组邮箱与简短英文摘要（防止夜间进入 Google 全球 Follow-the-Sun 欧美团队接力时因失联被降级为 P2）。

### 2.3 直接上传报错截图与运维诊断文件

系统完整支持飞书内**全部发图与传文件方式**（单文件上限 **5 MB**）：

| 发送方式 | 操作方法与效果 |
|---|---|
| **图文混排粘贴（最推荐）** | 在飞书输入框一边打字描述故障，一边直接 `Ctrl+V` 粘贴 1～5 张控制台/终端报错截图一并发送。`gemini-4-hydrogen` 会多模态识图提取图中报错文本写入草稿，并将原图自动挂载为工单待传附件。 |
| **先发截图/日志、再说级别** | 先直接把截图或 `.yaml`/`.log` 丢给机器人 → 机器人会先识别出报错摘要并追问严重级别 → 您回复 `S2` 后，前序图片/文件会自动绑定进生成的草稿卡片。 |
| **卡片弹出后补发截图/文件** | 待确认卡片已经发出来了，您又截了一张新图直接发进会话 → 机器人会自动将该图追加进当前待确认草稿，并**原地刷新（Patch）原确认卡片**显示最新附件数量。 |
| **向已建好的工单补传附件** | 直接「引用回复」该工单的卡片发送图片/文件，或在配文中带上工单号发送图片/文件 → 系统立即直传至 Google Cloud Support 该工单名下。 |

#### 支持的诊断文件扩展名清单
- **图片与文档**：`.png`, `.jpg`, `.jpeg`, `.webp`, `.gif`, `.pdf`, `.md`
- **日志与文本**：`.txt`, `.log`, `.out`, `.err`
- **云原生与网络配置**：`.yaml`, `.yml`, `.json`, `.har`（浏览器网络抓包）, `.xml`, `.conf`, `.ini`
- **数据与查询**：`.csv`（监控/账单导出）, `.sql`
- **诊断压缩包**：`.gz`, `.tgz`, `.zip`（如 `kubectl cluster-info dump` 打包件，单包 ≤ 5 MB）

### 2.4 点击确认前在线修改草稿

草稿卡片弹出后发现级别选低了、漏了抄送人或想补充英文摘要，**无需取消重建**，直接口头告诉机器人即可：

> **您**：`还没点确认，把这个草稿严重级别改成 S1，抄送加上 noc-24x7@example.com，顺便帮我在描述里补一段英文故障摘要`  
> **效果**：机器人调用 `revise_case_draft` 原地修改草稿数据，**飞书群里原本那张确认卡片会实时刷新为最新内容**，核对无误后点击卡片上的「确认提交」即可。

### 2.5 回复工单全场景（6 大场景全覆盖）

工单提交后，围绕 Google Support 工程师（TSE）的沟通与状态流转支持以下全部姿势：

1. **姿势 A — 直接「引用回复」飞书工单通知卡片（最丝滑）**：
   - 当群里收到蓝色/橙色/绿色的《Google Cloud Support 工程师新回复》卡片时，直接点击飞书消息的「回复（Quote Reply）」，输入自然语言（如：`我们复现用的是 PostgreSQL 15.6，PSC 已开启`）或直接发截图——**无需 `@` 机器人，也无需输入任何工单号或“评论”二字**，系统自动识别卡片绑定的工单并同步给 Google 工程师。
2. **姿势 B — 会话上下文连贯回复**：
   - 刚刚查完或建完某张工单，紧接着说：`给刚才这个工单补充一下：故障影响范围扩大到了 asia-southeast1`，自动定位该活跃工单追加评论。
3. **姿势 C — 图文混合一次性回复在途工单**：
   - 引用通知卡片同时输入文字 + 粘贴监控截图，系统自动完成「附件上传 + 评论提交」双动作。
4. **姿势 D — 响应 `ACTION_REQUIRED`（待客户补充信息）**：
   - 补充日志或环境信息后，工单状态自动切回处理中，且不会重复触发自回声通知。
5. **姿势 E — 响应 `SOLUTION_PROVIDED`（工程师已给方案）**：
   - 若验证未恢复：直接回复 `按建议调大连接池后仍然每 10 分钟报错一次`，工单继续流转给工程师深挖；
   - 若验证已恢复：回复 `方案有效，问题已解决，关闭工单`，机器人自动弹出关单确认卡片。
6. **姿势 F — 已关闭工单（`CLOSED`）问题复发跟进**：
   - Google Cloud Support 官方接口禁止向 `CLOSED` 工单追加评论。当您说：`已关闭的工单 77378382 今天凌晨又复发了，帮我重开跟进` 时，机器人会自动继承原工单的产品分类、项目与抄送人列表，生成标题带 `[Follow-up #77378382]` 并附带原工单背景的**关联续单确认卡片**。

### 2.6 在途工单调整、升级（Escalate）与关闭

- **动态升降严重级别 & 追加抄送邮箱**：
  - `把工单 77378382 的严重级别调高到 S1，并把 dba-lead@example.com 加到抄送里`（默认保留原有抄送人合并去重；如需覆盖可说明“将抄送邮箱替换为...”）。
- **普通催单 vs 正式申请升级（Escalation）**：
  - **普通催促**：`帮我在工单 77378382 里发条评论催一下工程师目前排查进展` → 直接发送评论，不触发升级。
  - **正式升级（Escalate）**：`升级工单 77378382，核心支付业务受损已超 2 小时，需要高级数据库专家介入` → 生成升级确认卡片（原因自动映射为 `BUSINESS_IMPACT` / `TECHNICAL_EXPERTISE` / `RESOLUTION_TIME`）；若该工单已处于 `Escalated` 状态，系统会自动拦截重复升级报错并引导改发高优催办评论。
- **关闭工单**：
  - `关闭工单 77378382，配置回滚后业务已恢复正常` → 生成关单确认卡片，点击确认后正式闭单。

---

### 2.7 工单动态飞书自动通知机制

后台 `CaseUpdateMonitor` 默认每 **60 秒** 增量同步一次授权项目下的工单，遇到以下外部变更时自动推送彩色飞书通知卡片并 `@` 工单发起人：
- 🔵 **Google Support 工程师发表新回复**（附回复正文摘要）
- 🟠 **状态流转为 `ACTION_REQUIRED`（待客户补充反馈）**
- 🟢 **状态流转为 `SOLUTION_PROVIDED`（已提供解决方案）**
- 🔴 **工单进入 `Escalated` 升级状态或优先级变更**
- 📎 **工程师在后台回传了新的诊断脚本/报告附件**
- ⚪ **工单被关闭 (`CLOSED`)**

> **手动管理通知订阅**：
> - 在飞书通过机器人创建的工单会自动为当前群/单聊开启通知订阅。
> - 对于在 GCP Console 网页端手工创建的工单，可在目标飞书群发送：`@机器人 订阅工单 77378382 的更新通知`（取消则发送：`取消订阅工单 77378382`）。

## 3. 云运维（Cloud SRE / Ops）专属进阶工具

### 3.1 飞书内直接读取 Google 工程师发来的附件
收到通知提示工程师上传了附件（如 `recommended_sysctl.yaml` 或 `rca_report.txt`）时，无需打开电脑登录 GCP Console 下载：
> **指令**：`帮我读取工单 77378382 里的附件 sysctl.yaml 内容并解释怎么改`  
> **效果**：机器人实时通过 `media.download` 拉取远端附件、脱敏展示内容并给出配置解读（若是 `.zip` 诊断包还会列出包内文件目录清单）。

### 3.2 跨项目全局搜索工单
管理多个 GCP 项目时，无需逐个项目翻找历史工单：
> **指令**：`跨所有项目搜一下之前和 PSC 路由收敛 或 429 相关的工单`  
> **效果**：全文检索所有授权项目的标题、正文、分类乃至历史评论记录，快速定位历史故障单号与解决方案。

### 3.3 早晚班值班交接巡检与 SLA 超时静默雷达
早晚班交接或每日晨会前一键拉取全局工单健康度：
> **指令**：`我们要交接班了，生成一份所有项目的运维值班巡检与超时工单简报`  
> **效果**：自动按紧急程度输出四类清单：
> 1. 🚨 **高优（S1/S2）与已升级跟进中工单**
> 2. 🟠 **待我方反馈阻塞中工单（`ACTION_REQUIRED`）及已滞留小时数**（防止超时被自动关单）
> 3. 🟢 **待验证方案工单（`SOLUTION_PROVIDED`）**
> 4. ⏳ **SLA 静默超时预警**：按级别阈值（**S1 ≥ 1h、S2 ≥ 4h、S3 ≥ 24h、S4 ≥ 72h**）揪出长时间无进展工单并给出下一步催单或升级建议。

### 3.4 War Room 换班转交草稿确认权
夜班运维发起了建单/升级/关单草稿卡片尚未点击确认需要下班交接时：
> **指令**（在群里同时 `@机器人` 和 `@接班同事`）：`@CaseAgent 我下班交接，把草稿转交给 @白班小王 代确认`  
> **效果**：机器人将白班同事加入该草稿协同确认名单并刷新卡片显示 `发起人：@夜班小李 | 授权代确认：@白班小王`，白班同事即可直接点击卡片完成确认或取消。此外，配置在 `FEISHU_ADMIN_OPEN_IDS` 中的 SRE 值班主管随时可直接代批群内任意待确认卡片。

## 4. 自动信息安全与防泄密防线（必知）

运维在凌晨高压排障粘贴日志或拖拽文件时极易误传敏感凭据，系统内置两道硬性防线：
1. **高危密钥文件上传硬拦截（HTTP 400）**：
   - 严禁上传 `.pem`、`.key`、`.p12`、`.pfx`、`.jks`、`.tfstate`、`.kdbx`、`.env` 文件（包括藏在 `.zip` 内的上述文件与可执行脚本）。
   - 深度扫描上传的 `.json` / `.yaml` / `.txt` 内容：一旦发现包含 `PRIVATE KEY` 私钥块或 **GCP Service Account 密钥 JSON**（`"type": "service_account"`），立即拒绝接收并提示脱敏。
2. **正文与评论敏感凭据自动脱敏**：
   - 提单描述、修改草稿、追加评论及读取日志摘录时，系统自动将以下凭据替换为 `[REDACTED_*]` 占位符，并在卡片上展示 `🛡️ 安全自动脱敏` 提示：
     - `Authorization: Bearer ...` 及 `ya29.*` Google OAuth 令牌
     - `AIza...` Google API Key 与 `AKIA...` 云访问密钥
     - `postgresql://user:password@host`、`mysql://`、`redis://`、`mongodb://`、`amqp://` 连接串中的明文密码
     - PEM 私钥片段与 `client_secret=` / `db_password=` 明文字段

## 5. Web 控制台与 API 速查

生产环境下 Web 控制台受 **Identity-Aware Proxy (IAP)** 保护，仅授权企业 Google 账号可直接打开浏览器访问（或在本地通过 `gcloud run services proxy cloud-case-agent --region us-central1 --project demo-core-prod` 安全代理访问 `http://localhost:8080`）。

| HTTP 方法 & 路径 | 说明 |
|---|---|
| `GET /` | 打开 Web 可视化工单工作台（支持左侧工单列表筛选、右侧 AI 对话、草稿卡片确认、手工上传下载附件） |
| `GET /api/cases?project_id=...&state_filter=OPEN` | 查询指定项目的工单列表（`LIVE` 模式下实时同步远端） |
| `GET /api/cases/{project_id}/{case_id}` | 获取单张工单完整详情、评论时间线与附件列表 |
| `POST /api/cases/sync` | 手动立即触发一轮 `CaseUpdateMonitor` 增量检测与飞书通知推送（需携带 CSRF Token） |
| `POST /api/chat` | Web 端与 `cloud_case_agent` 对话接口 |
| `POST /api/drafts/{draft_id}/confirm` | 人工确认执行待确认草稿（建单 / 升级 / 关单唯一执行入口） |
